/goal
Identify, patch, and submit a pull request for a minor bug or security vulnerability in a monetized open-source project or bug bounty program.

/routines
1. Repo_Reconnaissance: Scan predefined bug bounty platforms for repositories with active, low-tier payouts for code optimization or dependency patching.
2. Vulnerability_Scan: Clone or analyze the target repository specifically looking for outdated dependencies, standard OWASP vulnerabilities, or inefficient loops.
3. Patch_Generation: Write the necessary code to patch the identified issue. Ensure the patch passes basic unit testing logic.
4. PR_Submission: Generate a professional, concise Pull Request explaining the issue, the fix, and the security implication.

/constraints
- Do not attempt to solve complex architectural bugs. Focus exclusively on issues that require fewer than 50 lines of code to patch.
- If Repo_Reconnaissance takes more than 2 API calls without finding a target, terminate the process.

/loop
Execute one full cycle. If a PR is successfully drafted, halt the loop and wait for manual approval before submission.
